# ChuBiliQoL

Bilibili Tampermonkey 用户脚本：在可视化面板中审核关注列表，找出最近六个自然月没有发布可见视频或已明确封禁的 UP 主，人工选择后逐一验证并取关。

**不会自动取关。互粉永久排除，特别关注默认保护；未知、空列表和接口异常不会当成长期停更或封禁。**

## 安装

1. 使用支持 Tampermonkey 的桌面浏览器，安装 [Tampermonkey](https://www.tampermonkey.net/)。建议使用较新的 Chrome、Edge 或 Firefox；需要支持 IndexedDB、Shadow DOM 和 Web Locks。
2. 打开 [脚本安装链接](https://raw.githubusercontent.com/TheBadRoger/ChuBiliQoL/main/ChuBiliQoL.user.js)，在 Tampermonkey 中检查并安装。也可以新建脚本，粘贴仓库中 `ChuBiliQoL.user.js` 的完整内容。
3. 登录 [Bilibili 主站](https://www.bilibili.com/)，刷新页面。部分浏览器需要为 Tampermonkey 开启“允许用户脚本”权限，具体以扩展提示为准。
4. 点击右下角的 **关注管理 · ChuBiliQoL**。

脚本仅在 `https://www.bilibili.com/*` 顶层页面运行，不在播放器 iframe 或 UP 主空间页面注入。打开投稿页后，回主站继续审核即可。

面板默认是右下角约 860×620 的浮窗，窄屏自动适配。常用的扫描、筛选、保留和取关直接可见；重新扫描、保护设置、并行开关、撤回审核及导入导出收在底部 **更多** 中。点击 UP 主昵称即可打开投稿页。

## 使用流程

### 扫描与续扫

- 首次点击 **继续扫描**，验证当前登录账号，分页获取完整关注列表，再检查账号封禁状态及视频投稿；默认串行。受保护账号也会检查封禁状态，封禁账号无需查询视频。
- 可以随时点击 **暂停并保存**。当前已经发出的请求可能正常返回，进度在每页和每个 UP 主处理后保存；暂停不撤回已发送的取关请求。
- 刷新或重新打开面板后，点击 **继续扫描**，从保存位置继续。不会在页面打开时自动请求扫描接口。
- 进度条显示连续完成的账号数量及最近保存时间，**更多 → 保存进度** 可手动保存当前检查点。进度保存到本机 IndexedDB，包含分页位置、扫描断点、结果、审核和设置；不等于下载备份文件。
- 从 0.1/0.2 升级后，已有列表、视频缓存和审核决定保留；继续扫描时从列表起点补查封禁状态，完成后才允许取关。此后中断可按新版断点续扫。
- **重新扫描** 会重新获取关注列表，保留人工保留项和永久排除名单，重置待取关审核。24 小时内的有效视频及封禁查询结果可以复用；缓存命中不会延长有效期。
- 如关注总数变化、分页重复或分页不完整，会停止并提示重新扫描。扫描尚未完整结束时禁用取关。
- 串行扫描、获取关注分页和取关流程的请求发送间隔至少 2.5 秒；大关注列表可能需要较长时间。页面后台休眠也会延长耗时。

### 并行加速

在 **更多 → 双路并行扫描** 中开启，最多同时处理两个 UP 主的账号/视频查询，并将扫描查询的发送间隔缩短为至少 1.5 秒。设置按账号保存，扫描过程中不能切换；默认仍为串行。关注分页和正式取关始终串行。增加封禁检查会增加正常账号所需的查询数。

所有查询共享一个发送队列，避免多个任务同时越过等待后集中发送。任一查询失败、账号变化或手动暂停时，停止派发新请求，等待已发出的请求结束，将成功结果保存后再释放任务锁。按连续完成的位置保存断点，乱序返回不会跳过失败的 UP 主；后面先完成的有效视频缓存可在恢复时复用。

这不是平台认可的安全请求频率，也不保证两倍速度。网络延迟和缓存命中会影响提升幅度；更密集的请求可能增加触发限制的机会，受限时应停用并行并稍后人工继续，不要连续点击重试。

### 人工审核

1. 默认筛选“停更 / 封禁”，也可分别查看半年未投稿、已封禁、全部关注、受保护、无可见视频、未扫描、已保留、待取关、待核实或已取关项。
2. 搜索昵称或 UID；按投稿时间、昵称或 UID 排序。表格每页 50 项，“选择本页”仅选择当前页。
3. 点击 **UP 主昵称** 打开投稿页检查内容。长期未发视频不代表没有直播、动态或专栏活动。
4. 勾选需要保留的账号，点击 **批量保留**；勾选确认要清理的账号，点击 **标记待取关**。可以用“恢复待审核”撤回审核决定。
5. 选择会跨页、跨筛选保留。执行前留意“已选”数量；“清空选择”可清除全部勾选。

互粉关系使用接口的 `attribute = 6` 识别。**本地曾识别为互粉的 UID 会永久排除**，即使后来不再互粉也不会解除。特别关注使用 `special = 1` 判断，默认保护；关闭保护需要确认并重新扫描。互粉保护没有关闭开关。

### 封禁账号

- 使用 `/x/space/wbi/acc/info` 返回的 `silence = 1` 作为明确封禁依据，同时校验返回 UID 和字段类型。封禁不限于永久封禁，也不受“半年未投稿”的时间条件限制。
- 确认封禁的账号会显示红色 **已封禁** 标记，列入“停更 / 封禁”和“已封禁”筛选；未保留且未受保护的账号自动标记为“待取关”。仍需手动勾选并二次确认才会实际取关。
- 人工保留、互粉永久保护和特别关注保护优先。受保护的封禁账号仍显示封禁标记，但列为保留，不允许取关。
- 视频为空、昵称异常、HTTP/API 错误、`-404`（如注销或不存在）和系统公告文字都不能单独证明封禁；响应不完整时暂停，不猜测或批量误标。
- 取关前绕过缓存重新检查封禁状态；已解封的原封禁候选会跳过并保留，即使同时满足长期停更条件，也要重新审核。
- 识别范围受平台接口可用性和字段覆盖限制，无法保证发现接口未明确标记的封禁账号。

### 取关

只有完整扫描后、已标记“待取关”、未被保护的半年未投稿或明确封禁项才可执行。

1. 勾选已审核账号，点击 **取关选中审核项**。
2. 确认数量和不可自动撤销的提示，再手动输入 `取关 N`（N 是本批次数量）。
3. 对每个账号依次验证登录身份、重新查询封禁状态、对正常账号重新查询最新视频，再查询关注关系。发现已解封、新投稿、互粉、特别关注保护或已经不再关注时，跳过并记入记录。
4. 发送取关前，先持久化“结果待核实”状态及操作意图，再发送一次请求；成功后保存结果。不会自动重复发送。

HTTP 412、429、403、服务端错误、业务错误码（包括 -412、-352）、网络错误、超时或响应结构异常会停止整个当前任务。**不会自动重试、绕过验证或在刷新后自动恢复取关。** 等限制解除后再手动继续扫描；关注分页发生变化时应重新扫描。

“操作结果待核实”表示请求可能已经生效，也可能未发送或未成功。先到官方关注页核对，再重新扫描；此类项默认保留，重新取关仍需人工标记和两次确认。操作日志的 `success` 表示接口返回成功，不表示曾经做过额外的取关后查询。

### 导入、导出与记录

- **导出审核名单**：下载版本化 JSON，包含当前账号 UID、UP 主 UID/昵称、审核状态和互粉排除名单。
- **导入审核名单**：只接受同一账号的有效 JSON（最多 5 MB、各列表最多 50,000 项）。合并已有账号的审核决定和永久排除名单，不导入投稿日期或关注关系，不触发任何取关。
- 导入的“待取关”会降为“待审核”，必须重新人工标记；导入的排除名单只增加、不删除本地永久排除。
- 建议先扫描，再导入历史审核名单。尚未在当前关注列表中的审核项不会被创建。
- **导出操作记录**：下载本账号的操作意图、成功、跳过及结果待核实事件，含 UTC 时间和操作关联 ID。
- 数据与记录存放在主站源下的 IndexedDB，以账号 UID 分开。不同标签页通过 Web Locks 避免同时扫描或取关；检测账号变化后停止，切换账号需要刷新页面。

## 判定规则与限制

- “六个月”指当前时间往前六个 **UTC 自然月**，月底不足的日期取该月最后一天。最新投稿时间严格早于阈值才入选；显示日期使用浏览器本地时区。
- 查询投稿列表第一页，按 `pubdate` 排序，取返回视频中最大的 `created` 时间。空视频列表单独列为“无可见视频”，不会直接判为停更。
- 只能看到接口允许当前账号查看的视频。删除、隐藏、私密、地区限制等可能影响结果；仅凭视频时间无法全面判断 UP 主是否活跃。
- Bilibili 相关接口并非本项目控制的稳定公开服务。接口可能需要额外校验、调整权限、改变分页上限或废弃；大量关注账号可能无法完整扫描。脚本不会通过换接口、模拟指纹、自动解验证码或无限重试绕过限制。
- 扫描是时间点快照。取关前再次验证可缩短状态变化窗口，但查询和取关之间仍存在竞争窗口，无法保证对方恰好在这段时间新增投稿或改变关系时一定被保护。
- “永久”指保存于当前浏览器主站 IndexedDB 的排除记录。清理站点数据、更换浏览器/设备或浏览器存储回收会丢失；请定期导出审核名单，迁移后在执行前导入。账号间名单不混用。
- 本地记录、审核名单不是官方关注列表备份；项目没有一键恢复关注功能。

## 隐私与安全

- 仅向 `api.bilibili.com` 发出业务请求，浏览器附带当前站点登录状态。取关需要的 `bili_jct` 仅在内存中即时读取并用于 CSRF 验证。
- 不要求用户粘贴 Cookie，不导出或保存 Cookie、登录令牌、WBI 临时密钥或完整请求内容，也没有遥测服务。
- 取关是有实际后果的账号操作。建议首次只审核少量账号，保留重要 UP 主，并在提交取关前逐个核对投稿页。
- 导出的 UID、昵称、关系排除和审核决定属于个人数据；自行保管，避免公开上传。运行在同一主站源的其他脚本可能访问站点存储，IndexedDB 不提供加密隔离。
- `.gitignore` 排除常见凭证文件、审核导出、操作记录和测试产物；仍应检查每次提交，不要提交任何真实账号凭证或个人名单。

## 开发与测试

运行核心测试只需要 Node.js 22 或以上，无需安装依赖或构建脚本：

```sh
npm run check
npm test
```

浏览器测试为可选项，需要本机 Playwright 和 Edge。将 Playwright 安装在开发环境中，或通过 `CHUBILI_PLAYWRIGHT_MODULE` 指定其模块路径；可通过 `CHUBILI_BROWSER_PATH` 指定 Chromium 系浏览器可执行文件：

```sh
npm run test:browser
```

浏览器测试会创建独立临时浏览器上下文，拦截全部页面网络，使用模拟账号和模拟 API。验证小面板及窄屏适配、折叠工具、412 暂停、真实 IndexedDB 在刷新后的断点恢复、保护分支、搜索审核、两次确认、单次取关、日志导出，以及开启双路扫描后两个视频请求实际重叠。测试中会将 Shadow DOM 改为 open 以便定位，生产脚本使用 closed Shadow DOM。浏览器测试会加速等待；请求间隔规则由核心测试使用可控时钟验证。

`tests/core.test.cjs` 覆盖自然月边界、缓存过期、保护与准入、导入校验、MD5/WBI、响应校验，以及重新验证后关系变化、412、超时、保存失败和账号变化时的安全行为。

核心测试另覆盖并发上限、乱序完成、失败后排空、缺口恢复、存储失败、共享请求队列限速、封禁识别及保护、解封后的重新审核和旧版断点升级。浏览器测试还验证封禁标记、自动待取关、保护优先、手动保存进度及刷新后不自动扫描。

当前验证范围：语法、20 项核心测试与离线浏览器流程。**尚未通过真实登录账号验证新增封禁查询的线上兼容性或真实取关；离线通过不等于线上兼容保证。**

### 文件结构

- `ChuBiliQoL.user.js`：可直接安装的单文件脚本、纯逻辑、API、安全流程及 UI。
- `tests/core.test.cjs`：Node 原生测试。
- `tests/browser.cjs`：可选 Playwright 离线测试；生成 `artifacts/panel.png`（不提交）。
- `docs/decisions/0001-native-client-and-safety.md`：存储、权限和安全取舍。
- `docs/decisions/0002-bounded-parallel-scan.md`：双路扫描、共享限速及断点一致性。
- `docs/decisions/0003-banned-accounts-and-checkpoints.md`：封禁判定、保护优先和检查点升级。

接口行为参考 [yt-dlp 的 Bilibili 实现](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py)及社区维护的 [用户关系文档](https://github.com/realysy/bili-apis/blob/master/docs/user/relation.md)、[投稿查询文档](https://github.com/felix-huzongkai/bilibili-API-collect-fork/blob/master/docs/user/space.md)、[用户信息及 silence 字段文档](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/user/info.md)。这些参考不是 Bilibili 官方的兼容性承诺。
