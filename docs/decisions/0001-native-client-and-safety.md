# 0001：原生客户端、账号隔离与失败时停止

状态：已采用。日期：2026-10-14。

本记录描述 0.1.0 的决定；0.2.0 增加的可选双路扫描见 [0002](0002-bounded-parallel-scan.md)，其中扫描并发策略取代本文的全串行扫描策略，取关策略保持有效。

## 背景

本项目需要检查大量关注账号并允许人工批量取关。取关无法自动撤销，而网络失败无法证明服务器是否已经处理请求。用户要求原生 JavaScript、Shadow DOM、IndexedDB 和最少依赖。

## 决定

采用可直接安装的单文件用户脚本，不引入运行时库、构建器或后端。Shadow DOM 隔离面板样式；所有外部文本通过 `textContent` 或 DOM 属性设置，禁止拼接来自 API/导入文件的 HTML。WBI 签名所需的 MD5 使用 RFC 1321 算法，并与 Node 独立实现比对；不用于密码学安全存储。

脚本只运行于主站源，使 IndexedDB 和 Web Locks 在多个主站标签页间共享。IndexedDB 按账号保存一个原子检查点，日志独立追加；不使用易受容量限制的 localStorage。选择单对象检查点简化恢复一致性；每步保存会复制当前列表，大列表存在写放大，规模实测出现卡顿时再迁移到逐行存储。原生 fetch 的跨域 Cookie/CORS 行为受限制，因此仅使用 Tampermonkey 的 `GM.xmlHttpRequest` 访问固定 API 主机，不申请任意主机权限。

扫描先完成关注分页，再逐人检查视频，检查点指向下一个待处理位置。分页总数变化、重复或提前为空时停止。扫描缓存从实际查询时间计算 24 小时，使用缓存不延长有效期；取关前强制绕过缓存。

所有网络和业务错误都停止当前任务，不自动重试。每个取关先验证身份、最新投稿和关注关系；永久排除曾识别为互粉的账号，默认保护特别关注。写请求前持久化保留决定、待核实状态与日志意图，成功后记录结果；崩溃、超时或保存失败不能导致自动重放。重新发起取关必须再次人工审核和二次确认。

导入属于不可信输入，只允许同账号、受限大小的审核决定与附加排除名单；待取关决定降为待审核。不会导入可直接影响取关资格的投稿和关系信息。

## 取舍与限制

不使用后台代理、并发爬取或无限重试，扫描速度较慢，也不保证突破平台分页上限和风控。Web Locks 只能协调同源浏览器上下文，无法阻止其他浏览器、官方客户端或其他脚本操作账号。关系查询与取关不是服务端原子事务，仍有竞争窗口。

不使用远程数据库保存个人名单与凭证。站点数据清理后，本地永久排除和记录会丢失，因此提供可迁移的 JSON 导出。导出文件本身也含个人关系数据，不进入 Git。

## 验证

Node 原生测试验证纯规则和单项取关状态机；可选 Playwright 测试使用模拟 API 及真实浏览器 IndexedDB，验证暂停、刷新、恢复和审核取关流程。线上认证与平台响应仍需要维护者用真实环境进行小规模验收。
