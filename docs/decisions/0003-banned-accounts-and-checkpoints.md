# 0003：明确封禁账号与可见进度保存

状态：已采用。日期：2026-10-14。

0.3.1 补充：账号信息/稿件读取的 HTTP 404 或业务码 ±404 标记为“无法访问”，保存后继续扫描；不推断封禁，不自动重试。取关前这类查询返回 404 时跳过并保留该项。其他接口的 404 及请求限制错误仍停止当前任务。

## 背景

用户要求将所有已封禁账号列入待取关并特别标注，同时明确提供扫描进度保存。旧版仅检查投稿，不能将空视频或 API 错误等价为封禁。

## 决定

每个关注账号查询 WBI 用户信息接口并校验 UID，只有数值 `silence = 1` 才标为封禁。不从昵称、系统公告、视频可见性或错误码推断。正常响应必须有数值 0 或 1，否则停止。受保护账号同样检查封禁，以便完整展示标记。

封禁结果单独保存布尔值和真实检查时间，缓存 24 小时，命中不延长有效期。明确封禁账号跳过视频查询，以独立原因进入候选集合；没有人工保留且没有关系保护时自动标记待取关，但仍需手动勾选和二次确认。互粉和特别关注保护继续优先于封禁规则。

取关前重新查询封禁状态和关系；正常账号重新查视频。已经解封的原封禁候选改为保留并记录 `skipped-unbanned`，不依据其他原因悄悄继续取关。

保留原有逐页/逐账号 IndexedDB 检查点，增加持久化成功时间、进度条、最近保存时间、手动保存按钮和“暂停并保存”按钮。仅成功完成存储事务后更新内存中的最近保存时间。并行时沿用连续断点及乱序结果缓存。

检查点中的 `scanRules` 更新为 2；旧版保留列表、缓存、设置及审核状态，从索引 0 补查所有账号的封禁状态，标记未完成直到补查结束。数据库结构不变，无需升级 IndexedDB 版本。不能以旧版已完成状态省略新增检查。

## 取舍

额外用户信息查询增加请求数，仍受双路上限、共享限速和错误即停约束。不把注销/不存在（-404）归为封禁，不保证识别服务端未明确标记的封禁。导出审核名单仍仅包含审核与保护信息，不包含可伪造资格的封禁或投稿数据；完整扫描检查点保存在当前浏览器。

## 验证

核心测试覆盖 UID/字段校验、封禁与保护优先、缓存过期、解封重审、写入前状态更新及旧版升级。离线浏览器覆盖封禁标记/筛选、自动待取关、受保护项保留、手动保存进度和真实 IndexedDB 刷新恢复。未对真实账号进行封禁兼容性扫描或取关。
