# 0002：可选双路扫描与连续断点

状态：已采用。日期：2026-10-14。

## 背景

用户希望缩小面板并加快大量关注账号的扫描。原本逐人等待响应，在网络较慢时无法利用等待时间；直接并发又可能集中发出请求，在某个任务失败时跳过前面的未完成账号。

## 决定

默认串行，在“更多”中提供按账号保存的双路开关。仅对视频扫描启用最多两个工作任务；关注分页、取关前验证及取关写入始终串行。

所有 API 请求通过共享发送队列。串行间隔 2.5 秒，双路视频扫描阶段间隔 1.5 秒；同一时刻需要更新身份与 WBI 密钥的任务共享一个正在进行的身份请求。该频率是项目的本地限速选择，不代表平台保证。

第一个错误立即设置当前任务的停止原因，队列在等待前后检查停止状态。扫描任务等待所有已开始的工作结束，再释放跨标签页操作锁；不因并发引入重试。成功响应可以继续保存，未发出的请求不再发出。

结果保存按一个承诺链串行执行。只有从原断点连续完成的索引才推进 `cursor`；后方先完成的结果照常写入行缓存，失败缺口保持可恢复。无需改变 IndexedDB 版本或迁移旧检查点。

面板改为右下角 860×620 浮窗，窄屏按可视区域收缩。合并昵称与投稿链接，低频操作放入“更多”；保护与二次确认仍然保留。

## 取舍

未采用高并发、无限任务队列、自动重试或并行取关。双路模式可能更容易受到请求限制，用户需要主动开启，且不承诺加速倍数。已发出的查询最多还需等到 20 秒超时，暂停不会立即中断它们。

## 验证

核心测试使用受控承诺和时钟覆盖并发上限、乱序完成、错误后排空与恢复、存储失败和请求间隔；离线浏览器验证小面板、窄屏布局、折叠工具及两个视频请求重叠。未对真实账号压测或进行真实取关。
